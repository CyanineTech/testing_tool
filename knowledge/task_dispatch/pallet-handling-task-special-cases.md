# 托盘取放货任务专项

## 适用范围
- 适用于取货、放货、叉货、托盘对位、托盘识别、准备点和托盘事件链路问题。
- 用于把“托盘任务”从普通任务系统问题中单独拆出来，按托盘场景复盘。

## 历史复盘优先

- 任务问题优先围绕任务创建、卡住、恢复和人工干预的时间线复盘。
- 不要只因为任务最终完成或当前机器人在线，就忽略最初卡住时的真实断点。
- 应优先回看主机任务流、从机动作、事件回执和现场条件变化。

## 典型现象
- 任务派发正常，但总在托盘相关步骤失败。
- 同一任务类型在不同托盘、不同库位表现差异大。
- 托盘识别、插叉、抬叉、放货其中某一段反复失败。
- 现场换托盘、换摆放方式后成功率明显变化。

## 优先检查
1. 先确认失败发生在识别、进叉、抬叉、移动还是放货阶段。
2. 检查托盘规格、托盘脚、货物摆放、准备点和库位几何关系。
3. 结合 `low_level_status`、bag 和现场照片确认是几何问题还是底层状态问题。
4. 再看任务状态机是否收到了正确的托盘事件回执。

## 关键日志
- 托盘相关 bag / caution
- `default.launch`
- `mobile_base.launch`
- `/motor_control/low_level_status`
- 现场照片与视频

## 常见检索词
- 托盘任务失败
- 取货总失败
- 放货总失败
- 托盘识别不稳定
- 插叉失败
- 托盘事件卡住

## 判定口径
- 如果失败集中在托盘相关步骤，更像托盘任务专项问题，而不是普通派发异常。
- 如果托盘步骤前任务就已卡住，更像任务链路或主从调用问题。

## 常见根因
- 托盘规格或现场几何不匹配。
- 底层状态位、叉尖 / 叉限位或识别链路异常。
- 托盘专项任务状态机未收到完整回执。
- 参数边界过紧，导致不同托盘鲁棒性不足。

## 处理建议
1. 先按托盘任务阶段拆分问题，不要笼统说“任务失败”。
2. 优先收 bag、照片和失败时间点做几何与状态联合判断。
3. 修复后在同类托盘、同类库位和同类任务上复测。
