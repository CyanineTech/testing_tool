# 任务状态不推进 / 卡在中间态

## 适用范围

- 任务已经创建并进入系统，但长时间卡在某个步骤、某个状态或某个事件上不再推进。
- 适用于“任务不是没派发，而是派发后卡住”的问题。

## 历史复盘优先

- 如果任务后来恢复、人工干预后继续执行，优先回看任务卡住当时的时间线，而不是直接看当前任务状态。
- 先固定任务创建时间、卡住时间、恢复时间，再回看主机后端日志、任务状态回执和从机侧动作证据。
- 当前页面里“现在已经结束/当前在线”不能直接说明当时状态机没有卡住。

## 典型现象
- 任务状态停在等待、执行中、某个事件处理中不变化。
- 机器人在线，也可能有局部动作，但系统状态不继续前进。
- 前端看到任务存在，但一直不完成、不失败、不释放。
- 同类任务偶发恢复，表现出状态机或条件判断抖动。

## 优先检查

1. 先确认任务是否真的已派发到机器人，而不是还卡在派发前。
2. 检查当前任务步骤、事件类型和机器人实时状态是否匹配。
3. 检查是否有某个前置条件、事件回执、topic 更新或后端回调没有到。
4. 再结合任务系统日志、后端日志和从机 ROS 状态判断卡在哪一层。

## 关键日志
- 任务系统页面或任务状态接口日志
- `task_running_server` 日志
- 主机后端日志
- 从机 `default.launch`、`mobile_base.launch`
- 相关 topic / service 的实时状态

## 常见检索词

- 状态不推进
- 卡在执行中
- 卡在中间态
- 任务一直不结束
- 任务不完成
- 事件没回执
- 任务卡住了
- 执行到一半不动了
- 回复继续也没推进

## 判定口径

- 如果任务压根没到机器人，更像派发异常。
- 如果机器人已有动作但状态不变，更像状态机、回执或条件判断未满足。

## 常见根因
- 某个事件触发条件一直不满足。
- 后端或 ROS 回执未正确回传。
- 任务状态机进入异常分支后未退出。
- 依赖 topic / service 没更新，导致系统一直等待。

## 处理建议

1. 先明确卡住的是哪一层：派发、执行、事件还是回执。
2. 如果是条件不满足，优先查现场状态、topic 和传感器输入。
3. 如果是回执链路问题，继续查后端、Redis 和调用链。
4. 修复后用同类任务复测，确认状态能完整跑通。
