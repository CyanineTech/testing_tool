# 事件条件不满足 / 动作触发失败

## 适用范围
- 任务已进入执行阶段，但某个事件、动作或状态转换始终触发不起来。
- 适用于取货、放货、对齐、充电、电梯、传送等事件条件判断不满足的问题。

## 历史复盘优先

- 任务问题优先围绕任务创建、卡住、恢复和人工干预的时间线复盘。
- 不要只因为任务最终完成或当前机器人在线，就忽略最初卡住时的真实断点。
- 应优先回看主机任务流、从机动作、事件回执和现场条件变化。

## 典型现象
- 任务停在某个事件前，不继续执行。
- 机器人局部状态看起来正常，但系统一直等待条件满足。
- 现场动作已完成一部分，但状态机仍认为未达到要求。
- 同一事件在不同现场条件下成功率不稳定。

## 优先检查
1. 先确认卡住的是哪个事件类型、哪个条件字段。
2. 检查对应传感器、topic、状态位和现场几何条件是否真的满足。
3. 查看任务系统、后端日志和从机 ROS 状态，确认是否收到正确回执。
4. 再判断是条件阈值问题、状态机问题还是现场物理条件不满足。

## 关键日志
- 任务系统与后端日志
- 从机 `default.launch`、`mobile_base.launch`
- 相关传感器、状态位、event topic / service

## 常见检索词
- 事件不触发
- 条件不满足
- 动作没开始
- 一直等条件
- 事件卡住
- 状态位不对

## 判定口径
- 如果现场物理条件本身不满足，更像传感器、位置或动作前置问题。
- 如果条件明明满足但系统仍不推进，更像回执、阈值或状态机逻辑问题。

## 常见根因
- 传感器状态位未达到预期。
- 现场位置、托盘、对位或充电姿态不满足事件前置条件。
- 回执链路丢失，系统没有收到条件已满足的信号。
- 条件阈值设置过严或逻辑分支异常。

## 处理建议
1. 先确认条件本身是否真的满足，不要只看结果现象。
2. 如果是物理条件问题，优先修正现场状态、姿态或传感器输入。
3. 如果是逻辑链路问题，继续查回执和状态机推进点。
4. 修复后复测同事件多次，确认不是偶发通过。
