# RCS 任务不派发 / 调度异常

## 适用范围

- RCS 主机上的任务明明创建了，但没有下发到机器人。
- 调度中心、任务队列、后端服务或数据库链路异常，导致任务卡住。
- 机器人在线但迟迟收不到任务，或者任务状态一直停在等待中。

## 典型现象

- 任务已生成，但机器人端没有动作。
- 调度中心没有继续推进，任务状态卡在中间态。
- 后端日志提示任务提交成功，但机器人侧没有响应。
- 某些任务能执行，某些任务不能，表现出队列或数据链路不稳定。

## 历史复盘优先

- 如果问题已经过去，优先回看任务创建、派发、回执、状态推进发生时的日志，而不是直接看当前任务队列。
- 先固定任务发生时间、失败时间或恢复时间，再查对应时间窗口内的主机日志、调度日志和机器人状态回流。
- 当前队列为空或当前机器人在线，不等于当时派发链路没有断点。

## 优先检查

1. 历史问题先固定任务失败时间和对应时间窗口。
2. 先确认主机后端、调度中心和数据库是否都处于运行状态。
3. 看任务队列里是否真的有待派发任务，还是任务根本没进入调度环节。
4. 检查机器人在线状态、心跳和目标地图/位置是否满足派发条件。
5. 如果只在某一类任务上失败，再对照任务类型、路径规划和库位状态。

## 关键日志

- `~/backend_log/` 或主机后端日志目录
- `dispatch_center` 相关日志
- `task_running_server` 日志
- `docker ps`、`docker logs` 输出
- `rcs_task_system` 相关状态页面或接口日志
- 历史时间窗口内的任务创建、下发、回执和状态推进日志


## 常见检索词

- 任务不派发
- 任务没下去
- 调度异常
- 卡在等待
- 恢复后想查根因

## 常见根因

- 调度中心服务未正常工作。
- 后端服务、数据库或队列连接异常。
- 机器人状态不满足派发条件，例如离线、模式不对或任务前置条件缺失。
- 地图、库位、路径规划或任务参数配置异常。
- 个别任务类型的业务规则或状态机卡死。

## 处理建议

1. 先分辨是“任务没进入系统”还是“进入了但没派发出去”。
2. 历史问题优先还原任务时间线，再判断断点发生在哪一跳。
3. 如果调度中心或后端有异常，先恢复服务和基础链路。
4. 如果是机器人状态不满足，先查在线状态、模式和前置条件。
5. 如果只影响某一类任务，再对照任务系统规则和地图 / 库位配置。
6. 修复后检查同类任务是否连续恢复，避免只恢复单个实例。
