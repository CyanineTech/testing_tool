# 历史案例：任务已下发，但状态没有回流

## 适用范围
- 主机任务已经进入执行，但任务状态、事件回执或完成结果没有正确回到主机。
- 适用于“机器人好像动了，但系统看不到状态推进”的历史问题。

## 典型现象
- 机器人现场有动作，但主机侧状态一直停在原地。
- 单次任务可以局部执行，但任务系统不更新完成或失败。
- 用户看到的是“任务卡住”，但本质是状态回流链路异常。

## 优先检查
1. 先确认机器人现场是否真的已经开始执行。
2. 再检查从机 ROS、从机后端、主机后端之间的状态回流链路。
3. 判断是动作没执行完，还是执行完了但回执没回来。

## 关键日志
- 主机任务状态日志
- 从机后端日志
- 相关 event / state topic
- Redis 或 HTTP 回流日志

## 常见检索词
- 任务发下去了但状态没回
- 机器人动了但系统没更新
- 回执没回来
- 执行了但状态不变

## 判定口径
- 如果现场没动作，更像派发或条件问题。
- 如果现场有动作但主机无状态变化，更像回流链路问题。

## 常见根因
- 从机执行结果未正确回写到主机。
- 中间件、回调或状态同步链路中断。
- 任务状态机收到局部回执，但缺少关键完成信号。

## 处理建议
1. 先确认动作是否真的发生过。
2. 如果动作发生了，优先检查回流链路而不是继续查派发。
3. 修复后用同类任务复测，确认主机状态能完整推进。
