# 取货时无法叉货到位

## 适用范围

- AMR 在取货、插叉、托盘对位或叉货准备动作中，出现叉臂进不到位、反复进退、插入后仍判定失败。
- 常见于 302000222FN 这类“取货时无法叉货到位”问题，也适用于叉货准备点、托盘规格或货物摆放偏位相关故障。

## 历史复盘优先

- 任务问题优先围绕任务创建、卡住、恢复和人工干预的时间线复盘。
- 不要只因为任务最终完成或当前机器人在线，就忽略最初卡住时的真实断点。
- 应优先回看主机任务流、从机动作、事件回执和现场条件变化。

## 典型现象

- 机器人到达取货点后无法完成最后几厘米的插入动作。
- 叉货动作反复重试，但最终仍失败。
- 叉尖或叉限位传感器状态不符合预期。
- 现场托盘看起来有偏移、损坏，或者取货准备点和托盘实际位置不一致。

## 优先检查

1. 先确认是否能拿到对应时间段的 bag、not_permanent 日志和 low_level_status。
2. 检查 `/motor_control/low_level_status` 中的 `fork_tip`、`fork_limit`、`fork_stage` 和底层错误码。
3. 对照现场托盘规格、货物摆放位置和取货准备点坐标，确认是否存在几何偏差。
4. 再检查叉货动作对应的插入参数、速度和末端位姿是否过于保守或过于激进。

## 关键日志

- `~/log/not_permanent/<时间目录>/default.launch`
- `~/log/not_permanent/<时间目录>/mobile_base.launch`
- `~/log/permanent/lanyin.log`
- `~/autobag/` 中对应时间附近的 bag 或 caution bag
- `/motor_control/low_level_status` 的叉货相关字段


## 常见检索词

- 叉不到位
- 取货失败
- 最后几厘米进不去
- 托盘偏了
- 重复失败

## 常见根因

- 托盘规格与地图或参数预设不一致。
- 货物或托盘在现场发生偏位、歪斜、残缺。
- 取货准备点设置偏前或偏后，导致最后插入距离不对。
- 叉限位传感器、叉尖传感器或底层通信存在异常。
- 叉货动作参数过于保守，导致进入一半后无法继续。

## 处理建议

1. 先用 bag 和日志确认是“几何偏差”还是“底层传感器/通信异常”。
2. 如果是几何偏差，优先核对托盘规格、货物摆放和取货准备点。
3. 如果是传感器或底层异常，先看 USB / CAN / 电机链路，再决定是否做软恢复。
4. 如果需要调整动作参数，先只改最小范围的插入距离、速度或准备点，不要一次改太多。
5. 如果同一场景反复失败，记录时间点和现场照片，作为后续参数和地图回溯依据。
