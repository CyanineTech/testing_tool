# 机型参数 + 现场几何边界 联合判断

## 适用范围
- 同一任务在某些机型、某些点位、某些托盘或某些地图区域反复失败，但又不是纯硬件损坏。
- 适用于“参数边界、机型差异、现场几何”叠加导致的复杂问题。

## 典型现象
- 某机型在多数场景正常，只在特定点位或特定托盘上失败。
- 微调准备点、速度、插入距离、姿态后，成功率明显变化。
- 现场看起来像偶发，但换机型、换点位、换托盘后规律明显。

## 优先检查
1. 先确认问题是否和特定机型、特定地图点位或特定托盘类型强相关。
2. 再核机型参数、动作参数、现场尺寸和障碍物边界是否叠加到一起。
3. 对照机型差异页和现场几何页，判断当前更像机型固有边界，还是参数设置过紧。
4. 最后用同类任务在不同机型、不同点位做对照复测。

## 关键日志
- 相关任务 bag / caution
- `default.launch`
- `mobile_base.launch`
- `indv_params.yaml`
- 现场照片、托盘规格、点位配置

## 常见检索词
- 某机型某场景总失败
- 参数边界问题
- 同点位不同机型结果不同
- 调一点参数就好
- 现场几何放大问题

## 判定口径
- 如果只在特定机型上失败，更偏机型差异。
- 如果只在特定库位、托盘、障碍布局下失败，更偏现场几何边界。
- 如果微调参数后成功率剧变，更偏参数边界问题。

## 常见根因
- 机型运动学或执行机构差异放大了现场边界。
- 现场几何条件逼近参数极限。
- 参数设置本身没有错，但鲁棒性不足。

## 处理建议
1. 先做“机型 / 点位 / 托盘”三维对照，不要只盯单次失败。
2. 参数调整优先做最小步长变更，并记录对应场景。
3. 结论里明确是“机型差异主导”“现场几何主导”还是“参数边界主导”。
