# 错误码 + 场景 + Bag 联合判断

## 适用范围
- 现场已经拿到错误码、任务场景描述和对应时间段 bag / caution，但单看任一信息都还不足以下结论。
- 适用于“有错误码但不知道是不是根因”“有 bag 但不知道从哪里切入”的联合复盘。

## 历史复盘优先

- 这类页面默认服务历史故障复盘，优先固定故障时间、重启时间、任务时间和对应日志目录。
- 不要直接拿当前状态替代历史证据，尤其不要让恢复后的状态覆盖首发异常。
- 应优先按时间线还原故障过程，再结合当前状态做补充验证。

## 典型现象
- 同一个错误码在不同场景下含义不同。
- 错误码本身提示很泛，需要结合动作场景和 bag 才能确认方向。
- 现场能提供错误时间、任务描述和 bag，但排查入口不清晰。

## 优先检查
1. 先确认错误码出现的精确时间点、任务类型和机器人当时所在步骤。
2. 再从 bag 中对齐该时间点前后 `20s~60s` 的关键 topic、状态位和动作变化。
3. 对照 `error-codes.md`、`error-tracing-methods.md` 和相关场景页，判断该错误更像“直接根因”还是“次级表现”。
4. 最后再看同一时段内是否还有 USB、CAN、定位、任务链路等伴随异常。

## 关键日志
- `~/autobag/caution_*.bag.zip`
- 连续基础日志 bag
- `~/log/not_permanent/<时间目录>/default.launch`
- `~/log/not_permanent/<时间目录>/mobile_base.launch`
- `~/log/permanent/<开机时间>/error_monitor_server.launch`

## 常见检索词
- 错误码怎么结合 bag 看
- 同一个错误码不同场景
- 有错误码有 bag 但不会看
- caution 怎么判断根因
- 错误码是不是根因

## 判定口径
- 如果错误码出现前已有更早的链路异常，更像“结果错误码”而不是“首发根因”。
- 如果错误码与关键状态位、动作失败时间完全重合，更可能是主问题入口。

## 常见根因
- 错误码只是上层收敛后的统一报错，真正根因在底层链路或场景条件。
- 场景动作失败后触发的通用错误码掩盖了实际几何、传感器或任务问题。
- bag 只看单一 topic，忽略了错误前后的完整状态变化。

## 处理建议
1. 先按“时间轴”而不是按“错误码名”排查。
2. 错误码、场景、bag 三者至少要有两者互相印证再下判断。
3. 如果 bag 中前因不清楚，优先扩大前后时间窗口再复核。
4. 最终结论里要区分“首发异常”和“最终报错”。
