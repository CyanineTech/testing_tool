# 服务超时或不通

## 适用范围
- RCS 后端接口超时。
- 调度中心、任务执行、数据库或网关服务响应慢。
- 用户常见描述包括“服务不通”“接口超时”“请求卡住”“服务挂了”。

## 典型现象
- 飞书或前端操作后无返回。
- 任务下发后长时间没有状态变化。
- 后端日志出现超时、拒绝连接或反复重试。

## 历史复盘优先

- 如果用户描述里有“刚刚”“今天”“刚才”“某个时刻”“后来恢复”，优先按历史超时 / 历史不通复盘处理。
- 先固定请求发生时间，再回看对应时间窗口内的主机、容器、调度和数据库日志。
- 当前接口恢复正常，不代表当时没有超时或调用链断点。

## 优先检查
1. 历史问题先固定请求时间窗口，再看对应时间段日志。
2. 先确认目标服务实例是否还在运行。
3. 再看端口、容器、数据库和任务链路是否正常。
4. 如果只有某个接口慢，再看对应日志和请求时间点。

## 关键日志
- RCS 主机上的后端日志、调度中心日志、任务系统日志
- Docker 容器日志和端口状态
- 若是联动问题，再看消息链路和数据库状态
- 历史时间窗口内的 `supervisor`、`docker`、`kernel` 日志


## 常见检索词

- 服务超时
- 接口不通
- 请求卡住
- 后来恢复
- 后端超时

## 常见根因
- 服务进程异常退出或反复重启。
- 依赖服务不可用，导致请求堆积。
- 资源不足、线程阻塞或数据库响应慢。

## 处理建议
1. 先确认是历史单服务问题还是历史调用链问题。
2. 再按端口、容器、日志顺序逐层排查。
3. 如果影响任务执行，优先恢复主链路，再追根因。
