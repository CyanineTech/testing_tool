# 主机到从机后端不可达

## 适用范围
- RCS 主机需要调用从机 `backend_fastapi`，但接口不通、无响应或偶发不可达。
- 适用于主机端任务已生成，但无法把 way / point、状态请求或业务调用落到从机。

## 历史复盘优先

- 这类问题如果已经恢复，优先固定故障时间、重启时间或请求失败时间，再回看对应历史日志。
- 不要直接拿当前端口、当前容器或当前进程状态替代历史主机故障证据。
- 当前状态只适合作为补充，历史时间窗口内的调用链、服务链和依赖链证据更关键。

## 典型现象
- 主机日志提示访问从机接口失败。
- 从机本地服务看似正常，但主机侧请求超时或连接拒绝。
- 只有个别从机异常，其它从机正常。
- 任务派发到某台从机时明显更容易卡住。

## 优先检查
1. 先确认从机 `backend_fastapi` 本地是否在线、端口是否在监听。
2. 再从主机侧检查到该从机 IP、端口和路由是否可达。
3. 检查主从配置、主从 IP 映射和当前机器人在线状态。
4. 再判断是从机服务没起来、主从链路异常，还是端口被占用 / 被拦截。

## 关键日志
- 主机后端日志
- 从机后端日志
- `curl http://<slave_ip>:3737/...`
- `ss -lntp`
- `ip route`

## 常见检索词
- 主机调从机失败
- 从机后端不通
- slave backend 不可达
- 3737 不通
- 主机访问从机失败
- 某台从机接口超时

## 判定口径
- 如果从机本地端口都不在，更像从机服务状态问题。
- 如果从机本地正常但主机访问失败，更像主从链路、配置或网络问题。

## 常见根因
- 从机 `backend_fastapi` 未正常启动。
- 主机到从机链路异常或主从 IP 配置不一致。
- 从机端口监听异常或被错误占用。
- 某台从机自身网络抖动。

## 处理建议
1. 先在从机本地确认服务和端口。
2. 再从主机侧验证对该从机的实际访问。
3. 如果只影响单台从机，优先查该从机网络、配置和服务状态。
4. 修复后复测主机到从机的实际调用链，而不是只看端口通断。
