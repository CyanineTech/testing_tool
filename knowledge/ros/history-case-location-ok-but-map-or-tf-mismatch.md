# 历史案例：定位看似正常，但地图或 TF 不匹配

## 适用范围
- `/amcl_pose`、基础定位输出看起来还在，但导航、点位或姿态表现明显不对。
- 适用于“不是纯定位丢失，而是地图、TF 或切图后关系错位”的历史复盘。

## 典型现象
- 地图上有位置，但实际导航行为明显不合理。
- 定位值存在，但走不到点、朝向奇怪或路径绕行异常。
- 切图、换场景、重定位后问题更明显。

## 优先检查
1. 先确认定位值是否存在，再判断它是否与地图 / TF 关系真正一致。
2. 检查 `/map`、`/amcl_pose`、`/tf` 和切图流程。
3. 判断是定位本身错了，还是地图、TF、坐标系关系错了。

## 关键日志
- `/map`
- `/amcl_pose`
- `/tf`
- `default.launch`
- 地图服务和切图相关日志

## 常见检索词
- 定位看着正常但走不对
- 地图和定位对不上
- 切图后方向不对
- tf 对不上地图

## 判定口径
- 如果定位值有，但地图 / 姿态关系明显不对，更像 map 或 TF 不匹配。
- 如果定位值本身就漂移明显，更像定位链路问题。

## 常见根因
- 切图后 TF 或地图关系未完全刷新。
- 某一层坐标系仍引用旧地图关系。
- 地图资源与现场或定位链路不一致。

## 处理建议
1. 不要只看“定位有没有值”，要看地图 / TF 是否一致。
2. 先确认 map / tf / localization 的完整关系。
3. 修复后用实际导航路径复测，不只看静态位置。
