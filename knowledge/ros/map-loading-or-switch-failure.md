# 地图加载失败 / 切图失败

## 适用范围
- AMR 或 RCS 侧涉及地图加载、切换地图、重定位到新地图时失败。
- 适用于“地图文件在但加载不上”“切图后定位异常”“换图后任务跑不动”。

## 历史复盘优先

- ROS 运行态问题如果已经恢复，优先固定故障时间和对应 `not_permanent` 日志目录。
- 不要直接用当前 `rosnode list`、当前 topic 或当前 pose 替代历史故障证据。
- 应优先回看对应时间段的 `default.launch`、`mobile_base.launch`、`state_monitor_wrapper.launch` 和 bag。

## 典型现象
- 切图后机器人定位消失或导航直接失败。
- 地图加载接口返回成功，但实际 ROS 侧没有进入新地图状态。
- 新地图下任务、路径规划或定位数据明显异常。
- 同一张图可在部分设备使用，另一部分设备失败。

## 优先检查
1. 先确认目标地图文件、地图名和配置是否正确。
2. 检查切图前后 `/map`、`/amcl_pose`、定位相关节点是否正常。
3. 查看 `default.launch` 以及地图服务相关日志，确认是否有 map server、localization 或 TF 报错。
4. 再判断是地图资源缺失、切图流程失败，还是切图后定位链路未恢复。

## 关键日志
- 地图服务日志
- `~/log/not_permanent/<时间目录>/default.launch`
- `/map`
- `/amcl_pose`
- `rosnode list`

## 常见检索词
- 地图加载失败
- 切图失败
- 换图后定位不对
- map 没起来
- 新地图不能用
- 选图后没反应

## 判定口径
- 如果地图资源本身缺失或命名不对，更像地图文件 / 配置问题。
- 如果地图切换成功但定位不恢复，更像定位、TF 或切图后初始化问题。

## 常见根因
- 地图文件不存在、路径错误或配置不一致。
- 切图流程未完整刷新定位链路。
- 地图与现场不匹配，导致切图后立刻定位异常。
- map server、localization 或 TF 在切图后未恢复。

## 处理建议
1. 先核地图资源、命名和配置，再看运行态。
2. 如果切图后 topic / node 不正常，优先恢复地图和定位链路。
3. 修复后要用实际任务或定位复测，不要只看切图接口返回。
4. 若只有个别设备失败，再对比机器人本地配置差异。
