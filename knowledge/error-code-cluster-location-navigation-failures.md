# 错误码簇：定位 / 导航失败类

## 适用范围
- 适用于与定位丢失、路径规划失败、地图 / TF 关系异常、导航动作卡住相关的一组错误码和现场现象。
- 用于把“定位 / 导航异常”统一成一个错误码簇入口，而不是只看单个节点。

## 典型现象
- 错误码出现时，机器人位置、路径、朝向或导航行为明显异常。
- 同样的错误码，在不同地图、不同切图或不同 TF 状态下表现不同。
- 单看错误码解释不够，需要结合定位、地图和导航链路一起判断。

## 优先检查
1. 先确认错误码出现时机器人是否处于导航、对位或切图相关阶段。
2. 检查 `/amcl_pose`、`/map`、`/tf`、路径规划输出和局部控制表现。
3. 再判断是定位源异常、map / TF 不匹配，还是规划与现场空间冲突。

## 关键日志
- `/amcl_pose`
- `/map`
- `/tf`
- 路径规划相关 topic
- `default.launch`
- 对应 bag / caution

## 常见检索词
- 导航错误码
- 定位错误码
- 规划失败报码
- 地图对不上报码
- 导航卡住报码

## 判定口径
- 如果错误码前后定位和 TF 就已异常，更像定位 / map / TF 簇问题。
- 如果定位看着正常但动作异常，更可能是路线图、局部规划或现场几何冲突。

## 常见根因
- 定位链路异常。
- map / TF 不匹配。
- 规划结果和现场空间冲突。
- 切图、重定位或局部路径控制异常。

## 处理建议
1. 先把错误码归入定位 / 导航簇，再按定位、TF、map、规划四层细分。
2. 不要只看单个 topic，要看完整时间线。
3. 修复后至少在同一路线和同一地图上做复测。
