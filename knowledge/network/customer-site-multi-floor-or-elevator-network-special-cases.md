# 客户现场多楼层 / 电梯口网络专项

## 适用范围
- 适用于机器人需要跨楼层、进出电梯厅、电梯井口、楼层拐角等区域时出现的网络抖动问题。
- 用于区分“普通 WiFi 漫游”与“多楼层 / 电梯空间特有网络问题”。

## 历史复盘优先

- 网络问题大多发生在某个时间窗口或某段路线中，优先固定掉线时间、恢复时间和对应位置。
- 不要因为当前能 ping 或能 SSH，就直接排除当时的历史网络异常。
- 应优先回看对应时间段的 WiFi、VPN、SSH、系统日志和现场网络变化。

## 典型现象
- 机器人在楼层切换、电梯口等待、出电梯后更容易掉线。
- 同一楼层内部基本正常，但跨楼层任务成功率明显下降。
- 任务本身没问题，到了电梯区域链路就不稳定。

## 优先检查
1. 先确认掉线是否总与电梯口、楼层切换或井道附近相关。
2. 检查各楼层 AP 覆盖、漫游切换、1300D 路由器接入方式是否适配垂直场景。
3. 验证电梯口等待、进电梯、出电梯三个阶段的链路变化。
4. 再判断是遮挡、多径、跨楼层漫游还是客户现场 AP 策略问题。

## 关键日志
- `ping`
- `nmcli d show`
- `tailscale status`
- 掉线时间点与楼层位置记录

## 常见检索词
- 电梯口掉线
- 跨楼层掉线
- 出电梯后掉线
- 楼层切换网络差
- 电梯任务网络不稳

## 判定口径
- 如果掉线和楼层 / 电梯区域强绑定，更像多楼层现场专项问题。
- 如果无论在哪层都一样差，更像基础网络设计问题。

## 常见根因
- 楼层间 AP 策略不一致。
- 电梯井和金属结构造成强遮挡与多径反射。
- 楼层切换时漫游区覆盖不足。
- 电梯厅局部存在明显信号盲区。

## 处理建议
1. 不要只做平面路线验收，要做垂直场景验收。
2. 至少分别记录：楼层内、进电梯、出电梯三个阶段的网络表现。
3. 如果问题仅在电梯区域出现，优先做该区域专项优化。
