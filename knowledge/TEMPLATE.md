# 问题标题

标题建议：

1. 优先使用“用户会直接说的话 + 内部判断对象”的组合。
2. 标题里尽量包含一个具体症状词，不要只写很泛的技术名词。
3. 如果是高频问题，优先把“掉线 / 超时 / 不通 / 丢失 / 不派发 / 不到位”这类词写进标题。

示例：

- `WiFi 漫游后频繁掉线`
- `RCS 后端接口超时或不通`
- `AMR 定位丢失 / 位置跳变`
- `任务不派发 / 状态卡住`

不推荐：

- `网络问题分析`
- `后端故障记录`
- `定位模块异常`
- `任务系统相关`

## 适用范围
- 说明适用的机器人、主机、机型、版本或场景。

## 典型现象
- 列出用户常见说法。
- 列出现场可见现象。

## 优先检查
1. 第一条只读检查命令。
2. 第二条只读检查命令。
3. 第三条只读检查命令。

## 关键日志
- 指出优先查看的日志文件。
- 指出关键错误码、topic 或 bag 证据。

## 常见检索词
- 写 3 到 8 个用户常用说法。
- 优先写飞书提问里真实会出现的短语。

## 判定口径
- 出现什么现象时更像根因 A。
- 出现什么现象时更像根因 B。

## 常见根因
- 根因 1
- 根因 2
- 根因 3

## 处理建议
1. 先做什么。
2. 再做什么。
3. 什么情况下需要人工介入或停机。
