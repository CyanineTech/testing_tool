# 节点间距过密 / 路线图环形设计问题

## 适用范围
- 路线图中节点过密、避让点设计不合理、库位前画环或多点共享导致规划与调度异常。
- 适用于“单机还能勉强跑，多机容易乱”“局部区域总是重规划或互锁”的问题。

## 典型现象
- 路径在某一段反复跳变、重规划或抖动。
- 库位前、交汇点或狭窄通道总是更容易卡住。
- 多机同时进入某区域时更容易互相等待。
- 某些点位理论上可走，但现场表现为路线很不稳定。

## 优先检查
1. 先确认问题是否集中在某一段路线图，而不是全局规划异常。
2. 检查节点间距、节点离障碍物距离、边方向和权重是否合理。
3. 检查库位前是否存在环形结构、共享路径点或会车空间不足。
4. 再结合多机任务时间线，确认是图设计问题还是运行态调度冲突。

## 关键日志
- 路线图配置页面
- CBS / map_server / 调度中心日志
- 问题区域相关任务和规划记录

## 常见检索词
- 节点太密
- 路线图画环
- 路线抖动
- 路线老是重规划
- 库位前卡住
- 避让点不合理

## 判定口径
- 如果总在固定路段抖动或互锁，更像路线图设计问题。
- 如果图本身合理但偶发异常，更像调度链路或运行态干扰问题。

## 常见根因
- 节点间距过短，导致路径选择和切换不稳定。
- 库位前或交汇区画成环形结构。
- 多个库位或关键区域共用同一路径点。
- 避让点距离、权重、停靠朝向设置不合理。

## 处理建议
1. 优先从路线图结构改起，不要只靠调度规则硬兜底。
2. 如果是库位前设计问题，优先拆分路径点或取消环形结构。
3. 如果是节点过密，优先拉开间距并留足会车与避让空间。
4. 修改后至少安排单机和多机两种场景复测。
